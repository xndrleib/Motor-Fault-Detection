# SGDA-MotorDiag 0.1.6

Библиотека подготавливает спектры токовых записей, рассчитывает диагностические
частоты, синтезирует спектральные признаки неисправностей и применяет модели
классификации. Математические компоненты находятся в src, файловый интерфейс
и команды — в reporting, обучение — в experiments/train.py.

Требуется Python 3.11. Проектную среду создают командой python3.11 -m venv .venv.
Зависимости macOS и Linux закреплены в requirements-reporting-macos.txt
и requirements-reporting-linux.txt. После их установки исходники подключают
через `python -m pip install --no-deps -e .`.

Команда sgda-motordiag предоставляет prepare, synthesize и predict.
По умолчанию она выводит пути входов, параметры операции, размеры результатов
и рассчитанные показатели. Режим --format json сохраняет машинный вывод.
Полные manifest.json и metrics.json записываются независимо от формата терминала.
Дополнительно формируются spectrum_preview.csv и metrics.csv для просмотра.

Synthesize принимает необязательный --synthesis-config. Этот YAML содержит
логический include_negative_peaks; настройка действует только на данный синтез.
Без дополнительной конфигурации поведение прежнее. Подготовленные массивы
и конфигурации моделей остаются неизменными, строгая проверка predict сохраняется.

Параметры чтения файлов задают в разделе input_parameters YAML эксперимента:

```yaml
input_parameters:
  time_unit: milliseconds
  sampling_hz: 4096
  missing_current: drop
```

time_unit задаёт seconds или milliseconds; sampling_hz — частоту исходной
записи. missing_current задаёт reject (ошибка при пропуске тока) или drop
(удаление строки с отсутствующим током). Без этого раздела используются
seconds и reject, а частота проверяется по processing_parameters.f_sampling.
Параметры командной строки позволяют явно переопределить единицы и политику
пропусков. Пропущенные строки и обе частоты сохраняются в manifest.json;
программа не интерполирует ток и не выполняет передискретизацию.

Комплектные конфигурации сохраняют исходную сетку LIMAN-C 4096 Гц и расчётную
настройку БПФ 4098 Гц, использованную для обучения моделей. Для диагностики
отдельной записи теми же настройками передают --input-config с YAML
эксперимента. Параметры обработки в нём должны совпадать с конфигурацией модели.

В полной поставке данные LIMAN-C, модели и проверки находятся рядом с program.
Пошаговый порядок работы описан в её README и руководстве оператора.
Основная последовательность включает подготовку, синтез с рисунком и применение двух моделей.
Полная программа и методика испытаний содержит также ввод, повторяемость,
сравнения и проверки GPU в соответствующей программно-аппаратной среде.
