# FID Inputs — Outputs Overview

This document describes the artifacts produced by `build_fid_inputs.py`, their locations, naming, and how to interpret their contents.

## Where files live

All artifacts below are written to:
```
res/fid_inputs/
```


Paths are relative to the repository root.

## Window arrays

- **Real windows**: `real_<LOAD>_<FAULTCODE>.npy`  
  Example: `real_40_RBD.npy`

- **Synthetic windows**: `synth_<LOAD>_<FAULTCODE>.npy`  
  Example: `synth_40_ITSC.npy`

- **Frequencies (per engine)**: `{engine}_freqs.npy`  
  Example: `engine_2_freqs.npy`

Each `.npy` is a 2D array shaped `(num_windows, segment_length)`.

## Consolidated metadata (single CSVs)

- **Real windows metadata**: `real_windows_metadata.csv`  
  One row per saved **real** window across all `(load, fault)` groups and across all processed engines.

- **Synthetic windows metadata**: `synthetic_windows_metadata.csv`  
  One row per **synthetic** window generated by SGDA across all groups/engines.

### Common columns (subset)

- `engine_id` — engine that produced the window.
- `measurement_id`, `segment_idx` — source identifiers of the window (from segment metadata).
- `load_condition`, `phase` — as defined in the dataset and preprocessing.
- `fault_code` — short code for the fault (see map below).
- `target_file` — the `.npy` filename where the window resides.
- `row_in_file` — 0-based row index inside `target_file` (use with `numpy.load` to retrieve the correct row).

### Real-specific columns

- `state` — the real window’s label (e.g., `rotor bar defect`, `inter-turn short circuits`).

### Synthetic-specific columns

- `synthetic_fault` — the label injected by SGDA (e.g., `rotor bar defect`, `inter-turn short circuits`).
- `synthetic_load` — load level associated with the synthetic sample.
- `source_index` — row index in the `normal_meta` selection used to synthesize the window (for traceability).

## Fault code map

- `inter-turn short circuits` → `ITSC`  
- `rotor bar defect` → `RBD`

> Only the above faults are retained for FID in the current configuration.

## Other helpful files

- `{engine}_filtered_segments_metadata.csv` — per-engine, filtered segment metadata persisted for transparency.
- `index_map.json` — mapping from `<LOAD>_<FAULTCODE>` group keys to filtered row indices.  
  With consolidated metadata, most consumers can prefer `target_file` + `row_in_file`.

## Reproducing

Rebuild metadata and outputs:
```cli
python prepare_fid_windows.py --recreate-metadata
```
