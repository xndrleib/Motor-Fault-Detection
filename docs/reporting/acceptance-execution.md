# Испытания отчётной версии SGDA MotorDiag

Дата начала: 2026-09-28. Исходная база: denoising 376cc9f. Научные алгоритмы обучения, обработки спектра, нормализации и классификации сохраняются. Дополнительный интерфейс reporting обеспечивает проверку входов, отдельный каталог результатов и точное сопоставление сохранённых артефактов.

## Разрешённый объём

Пользователь поручил выполнить пункты 1–7 плана подготовки ПО и документов. Классы диагностического качества: Normal, ITSC, RBD. Остальные группы проверяются функционально на уровне синтеза. Новые научные методы и подбор удачного seed не входят в работу.

## Первый результат

Повторный инференс ResNet binary seed 42 из запуска 2025-06-03_01-01-40_train_1-phase-100-load-data-removeES-42-11 на заново подготовленных raw-записях воспроизвёл все 4032 сохранённых предсказания. Accuracy 0.9980158730, Macro-F1 0.9980158652, FPR 0.0. Голосование по имеющимся в сегментном test 71 исходной записи даёт 1.0, но это не валидация на новых независимых записях.

В 4 из 71 фазных raw-записей обнаружено по одному NaN тока. Исторический код применяет dropna. Новый интерфейс по умолчанию отклоняет такой ввод; флаг --missing-current legacy-drop явно воспроизводит старую обработку и записывает исходные позиции пропусков в manifest. Это сохраняет сравнимость старого эксперимента и не превращает удаление отсчёта в рекомендованную обработку новых измерений.

README набора engine_2 описывает отдельные физические двигатели для разных состояний. Результаты относятся к данному стендовому набору; перенос на новый двигатель и изолированный причинный эффект неисправности не установлены.

## Ограниченная GPU-проверка

- Вход: подготовленные 71 фазная запись, Normal/ITSC/RBD, фаза 1, нагрузка 100%; точные файлы и hash — prepared/manifest.json.
- Модель: ResNet, конфигурации training_configs/reporting/binary.yaml и multiclass.yaml, seed 42.
- Четыре обучения: два binary и два multiclass при одном seed. 30 эпох, batch 4096, исходные optimizer/scheduler/augmentation/split semantics.
- Не менять параметры по результату; это проверка фиксированных условий.
- Ресурсы: одна GPU V100, 2 CPU, один Slurm job, предел 60 минут. Четыре обучения последовательно в одной allocation.
- Очередь: rocky; no-requeue. Из-за текущих RealMemory=1 в scheduler явный --mem не задаётся, как предусмотрено HPC workflow.
- После первых 15 минут ожидания пересмотреть текущее squeue состояние и доступные разрешённые альтернативы; чужие jobs не изменять.
- scientific_start_event: первый forward/backward обучения после проверки source digests, prepared receipt и устройства. Ошибка импорта/пути до него — техническая попытка.
- Сохранить каждое обучение, test predictions, Macro-F1/Accuracy/FPR, model checkpoint, runtime и source receipt.
- Повторяемость: range метрик двух запусков в долях и процентных пунктах. Это наблюдение для двух повторов, не универсальная гарантия 1%.
- Латентность: 200 вызовов после 20 warmup, batch 1, resident GPU input → synchronized logits; отдельно 250 FFT bins (форма секундного окна) и 611 bins (историческое окно 10000/4098 с). Нулевые входы используются только для времени, не для качества.
- Не включать чистую kernel latency в утверждение о времени полного raw-file pipeline.
- При несовпадении источника, dataset или устройства остановить payload. При технической ошибке разрешён узкий repair/retry с новым output root и job id. Результаты до ошибки сохраняются.
- Противоречащие метрики не заменять лучшими; пересмотреть только их статус и интерпретацию, продолжить независимые документы.

## Что остаётся предметом согласования

Сентябрьское ТЗ содержит пороги инференса 1 и 10 мс, общее ТЗ — 0.1 мс; единая измеряемая операция не закреплена. Классы/нагрузки и единица метрики должны быть связаны с апрельской договорённостью. Допуск центра пика 1% ширины полосы конфликтует с разрешённым случайным смещением. Требуются уточнения по относительному baseline из раздела 7, экономии 80% и пояснительной записке. Эти пункты не объявляются выполненными по наличию кода или по выбору более удобного критерия.
